# GeorgePM · 阶段三：研发交付

把最终原型及有效产品决议转成研发可执行的规格，保留需求、实现和证据的区别。本包自包含，不依赖私人文档模板或本机门禁。

## 固定来源

读取原型、确认 PRD、设计系统、当前决议与已有交付稿；记录路径、版本和 SHA-256。继承角色端、平台与本次范围。没有原型时先说明依赖，可整理需求草稿，不声称完成原型交付。

最新有效产品决议约束产品行为；已确认的非占位原型是视觉/交互规格基线，设计系统是共享样式依据，PRD提供需求来源。mock/占位不覆盖确认需求。冲突列出具体两方来源和影响，待实质决策明确后同步，不凭文件时间猜测。

## 逐项转译

用 [交付模板](references/delivery-template.md) 建立 REQ → 页面/组件/状态 → 规则 → AC 的追溯。保留原始 ID 及源验收文字，新增验收单独编号并标明来源和确认状态。根据实际产品列用户页、共享弹层和后台配置，不为凑章节造功能。

每个用户功能写清定位、入口/前置、输入、业务规则、操作/状态、相关异常、Given/When/Then 验收与事件。检查加载、空、断网、错误、重连、限制、认证、审核/阻断等是否适用；不适用写原因，不虚构产品具备全部状态。后台按配置对象和控制单元写字段、默认、校验依赖、权限、生效范围及更新触发，不强套用户页结构。

产品规格定义 what、边界和验收；接口语义可建议，具体路径、并发/幂等方案和基础设施无技术确认时标“技术提案／待技术确认”。新业务默认值也保持建议状态。不能因为建议进入文档就称其已确认。

## 视觉证据与文档

默认交付单文件自包含 HTML：固定或可折叠目录、全局规范、用户功能/共享交互卡、实际涉及的后台配置、逻辑审查与验收专题；内联 CSS/JS 并内嵌真实截图，无远程资源依赖。用户明确要求 Markdown 时按其格式；无法真实渲染时可交付标明缺口的草稿，不称完整交付已验证。每个功能卡包含定位、入口/前置、业务规则、操作/状态、异常、GWT 验收与追溯。流程图和右侧真实截图按同功能配对；窄屏可上下排列。记录流程图与同功能真实截图的对应关系、来源版本、状态及视口。截图要实际访问目标原型捕获并查看内容；无浏览器或页面不可达则明确“缺少真实截图”，不伪造示意图冒充实测。

截图仅在独立截图会话隐藏评审外壳，不修改原型产品状态或布局。截图变更与正文变更分别登记；沿用旧截图需要证明该功能相关源码/样式/资源未变，并保留来源标签。HTML阅读文档检查目录定位、窄屏、长文/表格溢出和图片加载；静态检查不替代真实显示。

## 漏洞、变更与交接

逻辑审查逐项写“现象与来源／影响／建议或已确认决议／受影响契约／验证”。产品已确认、技术待签、实现差距分别列出；演示通过不等于后台接入或生产验收。

迭代只重做受影响规格及必要共享回归。规则撤销时同步活动原型说明、验收、事件、JSON等实际消费者；冻结历史保留并登记替代关系，不以追加新口径掩盖仍有效的旧指令。

交付前检查引用、覆盖、规则一致性和截图对应；用实际可用工具运行检查并绑定最终摘要。重要结论接受独立只读复核（可用时），没有独立复核则如实标记，不把自己的检查脚本称为独立评审。输出当前交付、未决与实现差距、验证范围及 HANDOFF；不自动上线或向研发发送消息。
