# GeorgePM · 阶段二：交互原型

以确认需求为输入，交付可体验、可追溯的原型。默认自包含单页 HTML；用户要求工程项目时明确入口、依赖和启动方式。本 Skill 不依赖特定设计工具、固定模型、私人组件库或外部账号。

## 开工与设计

继承阶段一项目性质、角色端、平台和本次范围，读取现有原型与设计系统。没有已确认 PRD 时，说明缺失，先整理关键需求；可在用户授权范围内做探索稿，但不得称其为正式阶段二完成。

说明当前输入、设计方向、演示边界和验证计划。已有确认及实现授权直接执行；只询问尚未解决、会实质改变结果的选择。无品牌规范时按场景提出简短视觉方向，标明自行选择的参数；已有产品按基线真实布局/样式迭代，不用默认风格覆盖。优先使用现有可用组件；缺少额外 Skill 不阻断本包。

## 需求落地

先按 [覆盖与验证模板](references/coverage-and-review.md) 将每条范围内 REQ/EP 映射到页面、真实组件、交互状态，或明确非视觉、范围外、占位及原因。纯后端规则不虚构 UI；状态切换不自动变成独立页面；只生成已授权的平台。

建立稳定组件/状态 ID。实现主路径、关键异常和退出恢复，按实际任务支持键盘、焦点、可读对比度和减少动态效果。链接有导航语义时提供正确 href，兼顾直接访问和返回；操作按钮不伪装成链接。

模拟数据、身份、支付、上传、服务端锁定等须在演示入口和相关反馈中标明；本地存储只代表该浏览器，不能宣称多用户同步或服务受理。单文件模式内联必要 CSS/JS/资源，不以 CDN 依赖冒充离线自包含。未经授权不接入外部写操作或部署。

## 内置评审说明与标注

提供产品浏览与评审入口。评审说明包含业务规则、交互说明、测试/开发边界；正文从同一结构化数据生成，避免复制多份规则。编号与真实组件按稳定 ID 双向关联，点击编号定位说明，点击有关联说明定位可见组件。无组件的规则只供阅读，不生成假编号/假高亮。

标注使用独立覆盖层，不接管产品组件原点击；支持键盘与清晰焦点，关闭评审时清理提示和计时。切页、滚动、缩放、弹层和重渲染后更新当前锚点；组件不可见时隐藏其标记。按实际端和可用空间布局，不固定套用某个项目的颜色、间距或设备尺寸。说明可点击定位时须实际可定位。

## 验证与迭代

实际运行最终候选，按覆盖表检查主路径、关键异常、导航、键盘、布局、标注联动及控制台/资源错误；异步操作等待可观察状态，不用固定延时充当就绪证明。无浏览器工具时交付未验证草稿，明确缺口，不写交互已通过。

结果绑定日期、最终文件摘要、视口/平台、用例与证据。静态检查、真实浏览器测试及独立只读复核分别记录，未做的检查不填通过。变更共享实现时检查实际消费者及例外；活动派生资料同步现行规则，冻结版本保持原文并登记替代关系。

原型与文档冲突时，以最新有效产品决议约束范围；已确认的非占位原型用于细化视觉/交互，设计系统约束共同样式，PRD约束需求。显式 mock 以确认 PRD 为准。新冲突列出两方来源，未裁决前不暗改业务。交付清单和 HANDOFF 说明当前版本、覆盖缺口、演示边界与后续阶段入口。
